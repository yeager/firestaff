# Firestaff Data Acquisition Checklist

This document tracks which original game data files Firestaff needs
to reach "code complete" for each of the five supported games, what
we already have on disk, and what is still missing.

It is intentionally **forward-looking**: an entry is "missing" if it
would unblock new work in `TODO.md`, even if we have enough files to
play the current runtime. The verification artifacts are stored under
`~/.firestaff/data/` for runtime use and
`~/.openclaw/data/firestaff-original-games/` for archive provenance.

## How to read this

| Column | Meaning |
|---|---|
| ✅ | present locally, hash-verified, runtime-ready |
| 🟡 | present as archive but not yet extracted / hash-locked |
| 🔴 | missing — needs acquisition |
| ⚪ | not needed (game/version out of scope for code-complete target) |

Hash column links to `docs/VERIFIED_HASHES.md` for SHA256 and to the
`asset_status_m12.c` table for MD5 (see
`docs/MD5_SHA256_HARMONIZATION.md`).

### DM1 acquisition gaps

1. **Atari ST 1.2 EN** is the most important platform gap because it
   is the only DM1 variant whose `GRAPHICS.DAT` uses LZW compression.
   Our Tier 2 #4 LZW decoder fix (commit `b3c4990e`) unblocked the
   decode path, but we still need an extracted local copy under
   `~/.firestaff/data/dm1-atari-st/` (or the
   `dm1-extras/atari-st-1.2-en/` raw folder) to feed real Atari ST
   bytes into `test_dm1_lzw_round_trip.c`.
2. **Amiga 2.0 EN** GRAPHICS.DAT hash is the same as PC 3.4 EN
   (`fa6b1aa2…`) but the 4bpp planar encoding differs and we have
   not yet exercised our Tier 2 #4 IMG5 decoder on a real Amiga
   asset. The archived `DungeonMasterAmiga20English.adf` needs
   un-ADF, then file-grab `graphics.dat` + `dungeon.dat`.
3. **Custom dungeons** for DM1 (Conflux, Tower of Chaos, etc.) are
   listed on dmweb as 60+ variants. Currently we ship none; we need
   at least Conflux II/III and one CSBWin custom dungeon to exercise
   `csbgraphics.dat` (Tier 3 work).

1. **PC 3.4 EN CSB** is the highest-value missing target. CSBWin

   tests only know the index range. A real Atari ST CSB GRAPHICS.DAT

## Acquisition workflow (for any new file)

1. Drop the file under `~/.firestaff/data/<game>/` (or
   `~/.firestaff/data/<game>-extras/<variant>/` for non-runtime
   variants).
2. Compute SHA256:
   `shasum -a 256 path/to/file`
3. Compute MD5 (only if the file is a runtime identity file):
   `md5 path/to/file`
4. Add a row to `docs/VERIFIED_HASHES.md` (table form for core,
   bullet form for extras).
5. If the file is runtime-detected, embed its MD5 in
   `src/shared/asset_status_m12.c` `g_requiredFiles[]` /
   `g_dm1GraphicsNames[]` / etc.
6. Run `python3 tools/asset-validate/compare_md5_to_sha256.py`
   — should report `PASS: all runtime MD5 + registry SHA256
   agree`.
7. Run `ctest -R asset_validate` to confirm the new file does
   not break the invariant.

picks (most unblocked downstream work) are:

1. **CSB PC 3.4 EN** (full CSB runtime target #2).
2. **CSB Utility Disk** (CMP + HTC + AMG runtime).

5. **Atari ST CSB GRAPHICS.DAT** (real hidden-code skip
   regression).
6. **DM2 Sega CD / Macintosh .moov** (animations + audio).

unblocked even without any of the above. Tier 3 work is where
the acquisition gaps will start to matter.
